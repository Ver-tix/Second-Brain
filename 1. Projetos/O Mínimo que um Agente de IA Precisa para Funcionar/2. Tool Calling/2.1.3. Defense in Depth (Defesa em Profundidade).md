## 1. Sanitização e Validação Dinâmica de Parâmetros

Nunca confie no JSON gerado pela LLM. Antes de repassar os argumentos para a função real em código, execute uma camada rigorosa de validação sintática e semântica.

```
[ Agente (JSON) ] ──► [ Validador (Ex: Pydantic) ] ──► [ Sanitização/Escapa ] ──► [ Execução ]
```

- **Validação por Esquema Estrito (Schema Enforcement):**
    
    Use bibliotecas de validação tipada em código (como **Pydantic** em Python ou **Zod** em TypeScript). Se o agente retornar um parâmetro com tipo incorreto ou fora da faixa permitida, o validador rejeita a chamada localmente sem nem tocar no banco/API.
    
- **Prevenção de Injeção de Código (SQL/Shell Injection):**
    
    - **NUNCA** concatene strings geradas pelo agente direto em queries SQL ou comandos de terminal.
        
    - Use **ORM / Prepared Statements** para banco de dados.
        
    - Para comandos de terminal, evite `shell=True` (em Python) e passe argumentos em arrays estruturados (`subprocess.run(["ls", "-l", path])`).
        
- **Regra de Sanitização de Caminhos de Arquivo (_Path Traversal_):**
    
    Se a ferramenta lê/escreve arquivos, garanta que o caminho solicitado não saia do diretório permitido (bloqueando tentativas de acesso como `../../etc/passwd`).
    

## 2. Controle de Acesso e Princípio do Menor Privilégio (_PoLP_)

O agente não deve herdar as credenciais de administrador da aplicação. Cada chamada deve rodar sob escopos delimitados.

- **Credenciais Escopadas:** Se a ferramenta consulta um banco de dados, use um usuário de banco que tenha acesso **apenas de leitura (`SELECT`)** e restrito às tabelas necessárias para aquela função.
    
- **Gatilhos de Confirmação por Humano (Human-in-the-Loop para Ações de Alto Risco):**
    
    Classifique as ferramentas em duas categorias de risco:
    

|**Categoria**|**Descrição**|**Exemplo de Ação**|**Fluxo de Execução**|
|---|---|---|---|
|**Read-Only / Baixo Risco**|Leitura e consulta de informações|`get_user_profile`, `search_knowledge_base`|**Automático**|
|**State-Changing / Alto Risco**|Modificação, escrita, transação financeira ou exclusão|`transfer_funds`, `delete_record`, `send_email`|**Requer Aprovação Humana (HITL)**|

> **Como funciona na prática:** Quando o agente invoca uma ação de alto risco, a ferramenta entra em pausa, dispara um alerta com a prévia da ação (ex: _"Deseja confirmar a transferência de R$ 500 para a conta X?"_) e só executa após o token de aprovação do usuário.

## 3. Isolamento da Execução (_Sandboxing_)

Para ferramentas que exigem execução de código dinâmico (como rodar scripts Python gerados pela IA ou raspar páginas web não confiáveis), a regra é: **Isolamento Total**.

**1.Containers e MicroVMs (E2B, Docker, Firecracker):**Limite o alcance do código em contêineres efémeros.

Execute o código em ambientes que são instanciados apenas para aquela tarefa e destruídos imediatamente após a conclusão. Soluções como **E2B Sandboxes**, **Modal** ou contêineres **Docker sem privilégios de root** impendem que o código acesse a máquina hospedeira.

**2.Restrição de Rede (Egress Filtering):**Previna exfiltração de dados e chamadas não autorizadas.

Bloqueie o acesso à rede interna da empresa. Se o código do agente precisa acessar a internet, libere apenas domínios ou IPs específicos (_Allowlist_) para evitar que a IA seja explorada para fazer requisições internas maliciosas (SSRF).

**3.Limites de Recursos (Timeouts & Memory Limits):**Proteja a infraestrutura contra ataques de Negação de Serviço (DoS).

Configure limites rígidos de tempo de CPU (ex: no máximo 10 segundos por execução) e de uso de memória RAM. Se o código entrar em um loop infinito, o ambiente mata o processo automaticamente.

## Resumo da Arquitetura de Segurança de Ferramentas

```
[ Entrada do Agente ]
         │
         ▼
[ 1. Validador de Schema (Pydantic / Zod) ] ──► (Invalido) ──► Retorna Erro ao Agente
         │
         ▼ (Valido)
[ 2. Checagem de Risco / HITL ] ─────────────► (Alto Risco) ─► Aguarda Aprovação Humana
         │
         ▼ (Baixo Risco / Aprovado)
[ 3. Ambiente Sandbox Isolado (Docker/E2B) ]
         │
         ▼
[ Execução Segura e Retorno Filtrado ]
```

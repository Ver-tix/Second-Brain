A estrutura de **Human-in-the-Loop (HITL)** para casos de esgotamento de tentativas é a "válvula de escape" que impede que o agente entre em loops infinitos, estoure o orçamento de tokens ou tome decisões equivocadas.

Em arquiteturas de agentes modernos, esse mecanismo funciona através do conceito de **Pausa e Estado Persistente (Interrupt & Resume)**.

## 1. O Ciclo de Transição para Intervenção Humana

Em vez de simplesmente falhar ou lançar um erro no código, o agente transiciona para um estado de **Aguardando Aprovação/Ajuda**.

```
[ Loop de Auto-Correção ]
         │
    (3ª Tentativa Falhou)
         │
         ▼
[ Disparo do Gatilho HITL ]
         │
         ├── 1. Congela o estado (Persiste histórico e variáveis)
         ├── 2. Cria uma notificação com o diagnóstico da falha
         └── 3. Define o status da tarefa como "PENDING_HUMAN_REVIEW"
         │
         ▼
[ Painel/Interface Humana ] ──► (Humano corrige parâmetro / dá dica / autoriza)
         │
         ▼
[ Retomada (Resume) ] ──► O agente acorda do ponto exato onde parou
```

## 2. A Estrutura da Notificação para o Humano

Para que a intervenção humana seja rápida e eficiente, o agente não deve apenas dizer _"Ocorreu um erro"_. Ele deve entregar um **Relatório de Diagnóstico Estruturado**:

```JSON
{
  "event": "HITL_INTERVENTION_REQUIRED",
  "task_id": "task_98765",
  "agent_id": "FinanceAgent_01",
  "reason": "EXHAUSTED_RETRY_LIMIT",
  "diagnostic_summary": {
    "original_goal": "Emitir nota fiscal para o cliente X",
    "failed_tool": "tax_service_api",
    "attempts_made": 3,
    "last_error": "CNPJ do destinatário está marcado como inativo na Receita Federal.",
    "agent_thought": "Tentei formatar o CNPJ e consultar a API de contingência, mas ambas falharam."
  },
  "action_required": {
    "type": "HUMAN_DECISION",
    "options": [
      { "action": "RETRY_WITH_NEW_INPUT", "label": "Fornecer um novo CNPJ válido" },
      { "action": "OVERRIDE_AND_SKIP", "label": "Pular emissão da NF e prosseguir" },
      { "action": "ABORT_TASK", "label": "Cancelar a tarefa completamente" }
    ]
  }
}
```

## 3. Os 3 Padrões de Invocação do HITL

Dependendo da complexidade do seu sistema, existem três formas principais de integrar o humano no fluxo:

### A. Pausa com Callback (Webhook / Fila de Mensagens)

O framework do agente (ex: LangGraph, n8n ou CrewAI) interrompe a execução, salva o estado em um banco de dados (SQLite/Redis) e envia um Webhook para um canal de comunicação (Slack, Teams, Discord, WhatsApp ou um Painel Admin).

  

> **Exemplo Prático:**
> Uma mensagem no Slack do time:
> _"⚠️ O Agente Financeiro travou ao emitir a NF do Cliente X após 3 tentativas. Motivo: CNPJ Inválido. [Botão: Corrigir CNPJ] [Botão: Cancelar]"_
> 
>   

### B. Injeção de Contexto (Human-as-a-Tool)

Se você estiver usando uma interface de bate-papo direta, a própria ferramenta de "Pedir Ajuda Humana" é registrada como uma **Tool** que o agente pode chamar quando percebe que esgotou os recursos.

- O agente chama a ferramenta `ask_human_operator(question="...")`.
- A execução congela e aguarda a entrada de texto do operador na tela.
- A resposta do operador entra no contexto do agente como o retorno da ferramenta, e ele continua o plano.
### C. Aprovação com Modificação de Estado (_State Editing_)

O operador humano não apenas responde um "Sim" ou "Não", mas tem permissão para **editar o estado interno** do agente antes de dar o comando de retorno:

1. O humano altera a variável `cnpj_cliente` diretamente no estado do agente.
2. Clica em "Resume".
3. O agente acorda executando diretamente o nó que falhou, usando a nova informação sem precisar refazer as etapas anteriores.

## 4. Diretrizes de Implementação no Prompt
No prompt do sistema, você estabelece as regras claras para quando o agente deve declarar falha e solicitar o gatilho:

```Markdown
### REGRAS PARA INTERVENÇÃO HUMANA (HITL)
1. Você tem um limite máximo de 3 tentativas de auto-correção para qualquer erro de ferramenta.
2. Na 3ª falha consecutiva:
   - NÃO tente novamente.
   - NÃO alucine uma resposta simulando sucesso.
   - Formate a saída usando o esquema `HITL_REQUEST`.
   - Especifique exatamente qual dado precisa ser corrigido ou qual decisão precisa ser tomada por um operador humano.
```

# O Cérebro (LLM): Pesos Treinados e Constitutional AI

## Onde termina o Modelo e onde começa o Harness?

Até aqui, tratamos "Modelo" e "Harness" como duas peças de uma equação: **Agente = LLM + Harness**. Mas essa linha divisória precisa ficar bem clara, porque é fácil confundir uma técnica de _treinamento_ com uma técnica de _runtime_.

## O que pertence ao Cérebro (LLM)

O LLM é o resultado de um processo de treinamento que já terminou antes do agente sequer existir como produto. Duas coisas vivem aqui, "gravadas" nos pesos do modelo:

1. **Pré-treinamento e Fine-tuning:** o conhecimento geral do mundo, adquirido processando bilhões de tokens.
2. **Constitutional AI / RLHF:** a camada de alinhamento de valores. O modelo é treinado usando um conjunto de princípios (a "constituição") para gerar suas próprias críticas e refinar respostas (RLAIF — _Reinforcement Learning from AI Feedback_), reforçando certos comportamentos e desencorajando outros.

**Ponto-chave:** essas capacidades e recusas já existem **antes de qualquer prompt ser enviado**. Um modelo com Constitutional AI resiste a um pedido nocivo mesmo sem nenhum "system prompt de segurança" — é comportamento de fábrica.

## O erro comum: confundir com "Constituição no System Prompt"

No documento [[6.1. Jailbreak e Prompt Injection (Direta e Indireta)]], a "Camada Intrínseca" é descrita como uma constituição escrita **dentro do System Prompt**. Tecnicamente isso não é Constitutional AI — é uma **instrução de runtime**, injetada a cada chamada, que vive no Harness (na camada de [[2.1. System Prompt e Identidade|Contexto]]).

||Constitutional AI (real)|"Constituição" no System Prompt|
|---|---|---|
|**Quando age**|Durante o treinamento do modelo|A cada chamada/requisição|
|**Onde vive**|Nos pesos do modelo|No texto injetado no contexto|
|**Pode ser sobrescrita pelo usuário?**|Não — já é parte do comportamento do modelo|Parcialmente vulnerável a jailbreak sem guardrails externos|
|**Camada arquitetural**|LLM (Cérebro)|Harness (Contexto / Guardrails)|

## Por que essa distinção importa na prática

Um harness mal projetado pode ter guardrails fracos mesmo rodando um modelo com bons valores treinados — as instruções de system prompt competem, no mesmo espaço de atenção, com o texto do usuário. Por isso a defesa robusta contra jailbreak combina as duas camadas:

1. Confiar no Constitutional AI do modelo como primeira linha (Cérebro).
2. Reforçar com Guardrails determinísticos em código, fora da LLM (Harness) — ver [[6.1. Jailbreak e Prevenção de Prompt Injection]].

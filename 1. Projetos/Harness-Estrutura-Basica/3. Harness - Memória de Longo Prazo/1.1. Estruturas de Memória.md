# Memória de Curto Prazo
## Antes de tudo, Uma Divisão

Como funciona nossa memória? Bem, nós temos memórias de curto e de longo prazo. 

Assim também, se queremos um agente de IA com uma boa estrutura de memória, devemos programá-lo com memórias tanto de curto como de longo prazo. 

Inicialmente, começaremos com a memória de curto prazo. Ela se chama **Buffer**
#### Leia mais aqui: [[2.2. Buffer - Memória de Curto Prazo]]

# Agora, vamos para as Classes de Memória de Longo Prazo

Nós já vimos que o **RAG vetorial** funciona muito bem para encontrar trechos de texto por "similaridade de significado" (proximidade semântica). Porém... 

## A busca por vetores tem uma limitação crítica: ela é ruim para entender relações estruturadas, conexões explícitas e hierarquias entre entidades.

Por exemplo: se você perguntar _"Qual é a relação entre o projeto X, a pessoa Y que o aprovou e o departamento Z que o executa?"_, o RAG por vetor pode trazer trechos soltos sobre X, Y e Z, mas pode falhar em ligar os pontos corretamente.

Para resolver essa falha de "ligar os pontos" de forma precisa e semântica, **que tipo de estrutura de dados (que não seja apenas texto vetorizado) poderíamos usar para mapear nós (entidades) e suas conexões (relacionamentos)?**

> Poderíamos usar **grafos de conhecimento**!

Exatamente. O **Grafo de Conhecimento** (_Knowledge Graph_) é perfeito para isso.

==Ele transforma o conhecimento em uma teia de **Nós** (ex: _Entidades_ como pessoas, projetos, sistemas) e **Arestas** (ex: _Relacionamentos_ como `APROVOU`, `PERTENCE_A`, `DEPENDES_DE`).==

==Ao combinar o RAG vetorial com Grafos de Conhecimento, nascia o que chamamos hoje de **GraphRAG**.==

Agora, vamos dar um passo a mais em direção à complexidade da memória humana.

Um Grafo de Conhecimento mapeia **fatos estáticos** (como as coisas se conectam no mundo). Mas o ser humano não vive apenas de fatos; nós também aprendemos com as **experiências que vivemos ao longo do tempo**.

## Imagine que seu agente tentou resolver um problema usando a Ferramenta A e falhou. Depois, tentou com a Ferramenta B e deu certo.

Se ele precisar consultar apenas fatos no Grafo de Conhecimento ou documentos no RAG, ele não aprenderá com o próprio erro.

**Como poderíamos estruturar uma "memória episódica" ou de aprendizado prático para o agente, de modo que ele consulte o histórico de suas próprias ações passadas antes de tomar uma nova decisão?**

>Ele poderia, após cada ação, ter uma **memória de registro**.

==Você acabou de conceituar perfeitamente o que a literatura de IA chama de **Memória Episódica** (_Episodic Memory_) ou **Logs de Reflexão / Replay de Experiências** (_Reflection / Self-Correction Memory_).==

Assim como a memória semântica guarda _fatos_ (o que as coisas são) e o Grafo guarda _relações_ (como se conectam), a memória episódica guarda **eventos e experiências** (o que aconteceu, quando aconteceu e qual foi o resultado).

Para fazer isso funcionar na prática, após concluir uma tarefa, o agente executa uma etapa de **Auto-Reflexão** (_Self-Reflection_). Ele salva um registro estruturado contendo três coisas:

1. **O Contexto/Ação:** "Tentei converter a planilha usando o método X."
2. **O Resultado:** "Falhou com o erro de formato Y."
3. **A Lição Aprendida:** "Sempre usar o método Z quando o formato for Y."

Agora, pense no seguinte desafio:

## Com o passar do tempo, esse agente vai acumular milhares desses registros episódicos e lições aprendidas. Se ele tentar consultar tudo o que já viveu a cada nova decisão, a janela de contexto estoura e o custo de tokens vai para o espaço.

**Como o agente deve decidir _quais_ episódios passados valem a pena ser resgatados do banco de dados na hora de resolver um problema novo no presente?**

Que critérios de seleção você usaria para resgatar a lembrança certa no momento certo?

> O Critério mais básico seria utilizar as lições que mais se encaixam ao contexto. Ele poderia ter um sistema que mostrasse quais dados do Reflection Log são os necessários. Seria um RAG do conhecimento episódico

==Sua intuição foi **precisíssima**. O que você acabou de conceituar não só faz total sentido, como é exatamente um dos padrões mais avançados em arquitetura de agentes de IA atualmente: a **Memória Episódica RAG** (ou _Episodic Memory Retrieval_).==

A ideia central é que o agente não precisa carregar todo o seu histórico no contexto o tempo todo (o que seria caro e geraria ruído). Em vez disso, ele consulta seu "passado" sob demanda.

### Como esse "RAG Episódico" Funciona na Prática

```text
[ Nova Tarefa / Contexto ]
			│
			▼
[ Busca Semântica por Similaridade ] ──► [ Banco de Dados de Reflexões (Vetorizado) ]
			│
			▼
[ Top Lições Aprendidas ]
			│
			▼
[ Injeção no Prompt ] ──► "Com base em erros passados, lembre-se de: X, Y e Z."	
```

### 1. Estruturação da Reflexão (O que é salvo)

Para que a busca funcione bem, o _Reflection Log_ não salva texto puro sem estrutura. Ele costuma armazenar a experiência em um formato estruturado:
- **Contexto/Gatilho:** O que o agente estava tentando fazer.
- **Erro/Falha:** O que deu errado.
- **Lição Aprendida (_Insight_):** O que deve ser feito de diferente no futuro.
### 2. Vetorização e Recuperação (O RAG)
Quando uma nova tarefa chega:
1. O sistema transforma o contexto atual em um vetor de significado (_embedding_).
2. Faz uma **busca por similaridade semântica** no banco de reflexões.
3. Recupera apenas as **2 ou 3 lições mais relevantes** para aquele cenário específico.
### 3. Injeção Dinâmica
Essas lições recuperadas entram na instrução do agente como diretrizes dinâmicas (ex: _"Atenção: em cenários parecidos com este no passado, você errou ao fazer X. Certifique-se de aplicar a regra Y"_).
### Referências no mundo real
Esse modelo é fundamentado em pesquisas recentes de inteligência artificial:
- **Reflexion (Shinn et al.):** Um framework onde o agente avalia suas próprias respostas, gera uma auto-reflexão verbal sobre os erros e a armazena em uma memória episódica para consultar em tentativas futuras.
- **Voyager (Wang et al.):** Um agente que joga Minecraft e constrói uma "biblioteca de habilidades/lições" vetorizada. Quando encontra um problema novo, ele usa RAG para buscar no seu histórico qual código ou lição passada resolve aquela situação.

==Seu raciocínio matou a charada: transformar a memória de longo prazo do agente em um sistema RAG focado em **lições e aprendizados episódicos** é a chave para evitar que ele cometa o mesmo erro duas vezes.==

Agora que passamos pelas memórias:
1. S**imples** (Buffer/Sumarizada), 
2. **Estruturadas** (Grafos) e 
3. **Episódicas** (Reflection Log RAG), 

Temos o panorama completo de **como o agente lembra**.

Mas isso nos leva a um novo problema prático sobre **como o agente pensa antes de agir**:

## Quando o agente recebe uma tarefa complexa, ele pode tentar responder imediatamente com base na memória, ou pode parar para planejar os passos antes de executar qualquer ferramenta.

Se ele apenas responder de primeira, a chance de erro ou alucinação em tarefas com múltiplas etapas é altíssima.

**Na sua visão, que mecanismo ou dinâmica de raciocínio poderíamos implementar no agente para que ele aprenda a "pensar alto", quebrar um problema grande em subtarefas menores e avaliar o próprio progresso antes de dar a resposta final?**

> Mecanismo de planejamento (quebra o objetivo em etapas menores), de CoT (chain-of-Thought) e um de orquestração

Sua capacidade de abstração está afiada! Você identificou e combinou exatamente as três peças fundamentais que a literatura de IA usa para resolver problemas complexos.

==O que você chamou de "mecanismo de planejamento", "CoT" e "orquestração" forma o tripé da **Cognição do Agente**.==

### 1. Chain-of-Thought (Cadeia de Pensamento)

O **CoT** é o hábito do agente de "pensar alto" em linguagem natural antes de tomar uma atitude. Em vez de ir direto para a resposta, ele escreve no seu próprio contexto o passo a passo lógico.

> **Exemplo sem CoT:** _"O resultado é 42."_ (Alta chance de erro se o cálculo for complexo)
> 
> **Exemplo com CoT:** _"Primeiro, preciso extrair o valor A. O valor A é 10. Depois, aplico a taxa de 20%... Portanto, o resultado é 42."_

### 2. Mecanismos de Planejamento (Planning)

Para tarefas longas, o CoT puro não basta. O agente precisa de algoritmos de planejamento. Existem duas formas clássicas de fazer isso:

- **Task Decomposition (Decomposição de Tarefas):** O agente pega um objetivo gigante (_"Crie um relatório de mercado sobre a empresa X"_) e cria uma lista encadeada de sub-tarefas atômicas:
    1. _Pesquisar dados financeiros recentes._
    2. _Analisar os principais concorrentes._
    3. _Sintetizar em um documento com formato padrão._
        
- **ReAct (Reasoning + Acting):** Um ciclo contínuo de **Pensar (Reason) $\rightarrow$ Agir (Act) $\rightarrow$ Observar o resultado (Observe)**. Ele olha a lista de tarefas, executa uma ferramenta, observa a resposta real do mundo e ajusta o plano se necessário.
    

### 3. Orquestração (O Maestro)
A orquestração entra quando o plano envolve **múltiplas especialidades**. Em vez de um único agente tentar planejar, pensar e executar tudo sozinho, temos um **Agente Orquestrador (Router / Supervisor)**.
- O Orquestrador recebe o objetivo principal e faz a decomposição.
- Ele delega o Passo 1 para o _Agente de Pesquisa_, o Passo 2 para o _Agente de Dados_, e assim por diante.
- Ele avalia a resposta de cada um antes de passar para a próxima etapa.

>[! ] 
>#### O Próximo Desafio
>Com planejamento, CoT e orquestração, o agente sabe **como quebrar e resolver um problema**. Mas e quando a execução **falha**?
>
>Imagine a seguinte situação: no meio de um plano de 5 etapas, o agente executa a etapa 3 (ex: buscar um arquivo via API) e recebe um erro `404 Not Found` ou um dado corrompido.

# Fim

No nível conceitual, encerramos nossa aula! Mapeamos todos os pilares essenciais que transformam um modelo "sem memória" (_stateless_) em um agente com retenção contínua e aprendizado.

Para consolidar tudo em uma visão de conjunto, cobrimos estes quatro níveis da taxonomia de memória de agentes:

## O Mapa Completo da Memória do Agente

```
                          ┌──────────────────────────┐
                          │    MEMÓRIA DO AGENTE     │
                          └────────────┬─────────────┘
                                       │
        ┌──────────────────────────────┼──────────────────────────────┐
        │                              │                              │
        ▼                              ▼                              ▼
┌──────────────┐               ┌──────────────┐             ┌──────────────┐
| CURTO PRAZO  |               |  LONGO PRAZO |             | LONGO PRAZO  |
|  (Sessão)    |               |  (Semântica) |             | (Episódica)  |
└───────┬──────┘               └───────┬──────┘             └───────┬──────┘
        │                              │                            │
  ┌─────┴─────┐                 ┌──────┴──────┐              ┌──────┴──────┐
  |  Buffer   |                 | RAG Vetorial|              | Reflection  |
  |    e      |                 |      +      |              |  Logs (RAG  |
  |Sumarização|                 |  GraphRAG   |              |  Episódico) |
  └───────────┘                 └─────────────┘              └─────────────┘
```

1. **Curto Prazo (Sessão Atual):**
    
    - **Buffer:** O histórico imediato de mensagens.
    - **Sumarização:** A compactação do texto para não estourar a janela de contexto nem o orçamento de tokens.
    
2. **Longo Prazo Semântica (Fatos e Relações):**
    - **RAG Vetorial:** Recuperação por proximidade de significado (ideal para buscar trechos de documentos).
    - **GraphRAG (Grafos de Conhecimento):** Mapeamento de nós e conexões exatas (ideal para entender hierarquias e como entidades se relacionam).
3. **Longo Prazo Episódica (Experiências e Aprendizado):**
    - **Reflection Logs (RAG Episódico):** A biblioteca de erros e sucessos do próprio agente. Ele consulta suas lições passadas sob demanda antes de agir, evitando cometer o mesmo erro duas vezes.
